Context: Projects organize planning work, tasks can have subtasks, and tasks can depend on other tasks. This record describes observed behavior; the historical reason for the original choice is not established by these sources.

Observed decision: Store project and task parent links and task_dependencies in PostgreSQL. Reject dependency cycles. Keep active task nesting flat: top-level tasks may have subtasks, but a subtask may not have children. Active parents with unfinished direct subtasks (todo, in_progress, or blocked) automatically become blocked and cannot explicitly start until those children close, are deleted, or detach. Done, cancelled, and deleted children do not block. Normalize eligible existing todo/in_progress parents through the same automatic policy while preserving manually blocked parents, terminal states, and frozen closed ancestor trees. Gate task completion on closing open descendants and project completion on closing descendant projects and tasks. Derive next actionable tasks recursively across eligible project subtrees, distinguishing prerequisite blocking and the open-descendant completion gate; automatically blocked parents appear only when blocked diagnostics are requested. Subtasks remain actionable beneath an otherwise eligible parent.

Explicit project archival recursively archives active descendant projects, including completed projects, and cancels active non-done tasks throughout the project and task hierarchy. Explicit task cancellation cancels active non-done subtasks. Preserve done cascade-descendant tasks, including their completion and update timestamps, and leave soft-deleted rows untouched. An explicitly cancelled root task may transition from done according to the existing API semantics. Preserve prerequisite edges; cancellation does not traverse dependency edges, while normal readiness recomputation includes dependents of all actually changed tasks.

Require reopening a cancelled parent before creating, moving, reparenting, or reopening an unfinished subtask beneath it. Reject the requested unfinished write with TASK_OPEN_UNDER_CANCELLED_TASK rather than silently cancelling it. Completed children may remain under a cancelled parent. Reopening the parent does not reopen its children. Preserve the separate done-parent, closed-project, flat-subtask and parent-eligibility rules, and verify placement ownership before revealing parent lifecycle state.

Enforce cascades and cancelled-parent closure prospectively through database triggers, without backfilling historical rows. Explicit repeated terminal status requests normalize descendants; application metadata-only updates carry transaction-local status intent so they do not sweep historical descendants. Ordered AFTER propagation completes descendants before closure checks and avoids rewriting pending outer UPDATE targets when a statement includes both parent and child. Use deterministic project-before-task and root-to-leaf locking, suppress recursive propagation, and recompute readiness over the actual changed task seeds. Core single and batch updates, direct SQL, REST, MCP and audit reverts share this authority and preserve atomic per-entity audit and canonical outbox attribution.

Use one database canStartSubtasks predicate for child starts, running-child restoration/reparenting, readiness summaries, and next-task discovery: an active open todo/in_progress parent, or an automatically blocked parent, with no open direct prerequisites, manual block, or closed task/project ancestor. Preserve the child's own prerequisite and placement checks. Existing running children are not paused when the parent later becomes ineligible. Recompute both parents on child placement changes. When final subtask and prerequisite blockers clear, an automatically blocked parent returns to todo; progress and completion remain explicit. Publish derived inProgressSubtaskCount and canStartSubtasks in single and batched readiness summaries so unloaded children require no presentation-state persistence or unbounded fetches. Automatic-effect reasons identify subtask, dependency, or combined causes.

Project pause is an atomic database lifecycle operation. Store own_paused separately from the effective active/paused status: an explicit paused request establishes independent intent even if already inherited, active clears that intent, and metadata updates retain it. Effective pause propagates through live open descendant projects, preserving completed/archived descendants and soft-deleted history. Stop effective project mutation at terminal project branches and task mutation beneath closed task/project ancestry, preserving historical open descendants in those frozen branches. The prospective running refusal separately reads every live descendant, including frozen branches. A closed root must reopen to active before pausing. Resume only inherited pauses and retain independent child pauses or remaining paused ancestry. Reject the entire pause if any affected task or subtask is in_progress. Creation, reparenting, project and task moves (including batch), reopening and restore use the same authority; pending work entering paused ancestry becomes paused/automatically blocked, running placement or restore fails, and moving out reconciles readiness. Project and task creation/update results are read from canonical state after AFTER-trigger propagation. Restores retain stored pause and automatic/manual task attribution rather than establishing repeated explicit status intent. Raw own_paused-only writes share the prospective guards and reconciliation. Private audit replay can restore a root-targeted boolean intent, including false when inherited effective status remains paused; the private replay authority does not bypass lifecycle guards.

Add paused project ancestry to automatic task blockers and the database canStartSubtasks predicate. Resume returns only eligible automatically blocked tasks to todo after project, prerequisite and subtask causes clear. Retain manual blocks and preserve done/cancelled task rows and their timestamps throughout direct and transitive pause-origin readiness recomputation. Scope and restore the origin setting around the operation; subsequent unrelated dependency edits in the same transaction retain the established V029 done-dependent behavior, including ordinary dependency operations inside paused ancestry.

A shared transaction advisory gate serializes planning writes before tuple locks, including raw multi-row project/task/dependency statements and application snapshot writers before SELECT FOR UPDATE. A global planning gate intentionally covers unassigned tasks and statements spanning workspaces; it trades parallel planning write throughput for a complete ordering across those scopes. Within that gate use project-before-task and root-to-leaf row locks, ordered AFTER propagation, and recursive suppression. Normal per-entity audit and canonical outbox triggers remain enabled and commit or roll back with the cascade. Install prospective rules and their migration ledger entry atomically in V035; historical normalization is a separate ordered migration before serving.
V036 normalizes historical pause before serving: each already paused eligible project owns its intent; eligible open descendants inherit pause and nonterminal tasks/subtasks become automatically blocked, including administratively converted legacy running rows. Preserve manual blocks, terminal rows and timestamps, deleted rows and frozen branches, and scoped terminal protection for transitive readiness effects. Capture excluded legacy paused identities in a sparse FK-linked retained-intent relation without rewriting their entity rows or historical events. Materialize and consume that provenance atomically when restore, reparent-out or ancestor reopening makes the record eligible; prospective running conflicts roll back entity, provenance and event changes. Metadata-only writes retain it, explicit active clears it, and modern inherited pauses never receive it. Private lookup and retained replay bind workspace and project identity; physical purge removes retained metadata. Reuse the V035 guard/body through a forward wrapper. Administrative normalization briefly disables only the named project pause cascade and task paused-placement triggers inside its transaction, keeps audit/outbox enabled, restores the guards and scoped status intent, and registers V036 before COMMIT. Migration-local change attribution produces ordinary system outbox events; failure at ledger insertion rolls back the additive schema, provenance, normalized rows and events. Runner skip/retry does not repeat effects.
Expose canonical project mutation results as the existing flattened Project with bounded pause_effects: truthful total counts, deterministic samples of at most twenty projects and twenty tasks, continuation flags, and remaining independent/ancestor pause. Capture before/after project and task readiness under the shared planning gate, including previously frozen targets that can become eligible on reopen or reparent. Task diagnostics and automatic-effect comparisons carry project pause alongside prerequisite and subtask causes; cause additions/removals remain visible while a task stays blocked. Single and batch running rollups include all live descendants, including frozen branches, and next-task diagnostics retain paused candidates while ordinary actionable results exclude them.

For project audit replay, authorize the entity workspace before decoding private provenance. Metadata snapshots preserve current pause intent and do not request unchanged historical placement. Actual intent transitions restore typed own_paused and retained_paused through a workspace/project-bound private core helper and the normal lifecycle gates; public mutation DTOs cannot write these fields. New project audit snapshots in V037 include retained provenance without rewriting historical rows or generic audits for other entities. Capture both marker values around the BEFORE intent phase, correlate UPDATE/DELETE by tuple version rather than trigger depth, and audit before recursive AFTER propagation. Normalize nested materialization snapshots to settled own=true/retained=false. Statement tokens clean conflict-only, suppressed and zero-row captures while preserving pending outer versions; rollback restores captures and scope. Preserve ordinary request/actor/workspace/cause attribution and one audit per actual row transition. Keep original-root full live project/task locks and projected/effective pause running veto separate from eligible mutation roots. Frozen deferred replay retains historical rows and marker intent; effective reconciliation and marker consumption wait until restoration/reparent/reopening makes the branch eligible. Install the forward authority and audit hooks and ledger atomically.

Legacy project metadata replays remain usable. An old active snapshot or known independent own pause is unambiguous; pre-V037 paused snapshots with known own=false and missing retained provenance cannot distinguish inherited from removed deferred intent. After authorization, reject only those ambiguous transitions with audit_pause_provenance_missing (409), and reject malformed canonical booleans with audit_pause_provenance_invalid. Require an explicit intended status rather than inferring retained intent from paused plus own=false.

Consequences: The hierarchy and prerequisite graph make work order explicit. Completion remains a deliberate gated transition; archive and cancel explicitly close unfinished hierarchy work while retaining completed task history. Invalid placement and lifecycle transitions fail with structured guidance. Cascade updates, readiness effects, audit records and outbox events commit or roll back together.
