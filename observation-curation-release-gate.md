## Isolated real-server two-tab browser smoke

An isolated real `stack exec hmem-server -- --dev --port 53606` server ran at `http://127.0.0.1:53606` with a sandbox PostgreSQL instance on ephemeral port `64657`. REST seeded two deterministic Observations in the Demo workspace, each with ordered subjects `file:src/ReleaseSmoke.elm` and `glob:src/**/*.elm`; no credentials or tokens were used or recorded. Playwright opened two real browser tabs. Before mutation, Shared subjects showed both the file and glob facets with two Observations each; opening the file facet produced two exact-subject results. Concrete-path matching `src/ReleaseSmoke.elm` produced the same two Observations under both file and glob evidence groups, and selecting one produced the direct link `#tab=observations&observation=…` with immutable workspace, ordered subjects, Git SHA, created, and updated display.

Tab 0 edited the surviving seeded Observation to the dirty draft `tab zero dirty draft`. Tab 1 saved `tab one foreign update` through the real UI. Returning to tab 0 showed the current server content in the list, `Results may have changed`, and the alert “This observation changed elsewhere. Your draft is preserved; choose how to continue before saving.” Its dirty text remained intact and Save was guarded behind `Use latest version` or `Keep my draft`. This is a real two-tab mutation, not an intercepted fixture.

The destructive dialog had the accessible name “Delete observation permanently?”, initially focused Cancel, and was dismissed both with Escape and by Cancel; focus returned to Delete observation. A separate foreign REST `DELETE` of the other seeded Observation returned HTTP 200 while its detail/match view was active. The live UI cleared its direct-detail hash and reduced the current concrete-path file and glob groups from two to one; after targeted mode refresh, the deleted content was absent from the unfiltered flat list and exact-subject result, while both shared facets reported one remaining Observation. The server log for the two-tab update recorded a PUT plus observation and entity GETs; it did not show a workspace-wide reload. The visible status remained the targeted `Results may have changed` / `Refresh results` reconciliation affordance.

A fresh isolated repeat used the same HTTP port 53606 and a new sandbox PostgreSQL port 50855. At desktop 1440×900 and narrow 390×844, the real direct-detail page retained the Observation browse-mode buttons, filters, cards, immutable provenance, and Edit/Delete controls in the accessibility tree; no control was hidden or replaced. Two tabs then held the same seeded target: tab 0 on exact subject and tab 1 on concrete-path match/detail. A foreign REST DELETE returned HTTP 200. In both tabs the direct-detail hash was cleared. Tab 0 then showed the exact result reduced from two to one and the unfiltered flat list at four items, containing only the surviving seeded peer. Tab 1 showed the concrete-path result reduced to one, with both the file and glob evidence groups at one, and its Shared subjects facet view likewise reported one Observation for each seeded subject. These observations deliberately divide the five discovery surfaces between the two live tabs: tab 0 verified flat, exact, and cleared detail; tab 1 verified match, facets, and cleared detail.

Both tabs were closed and the local server was interrupted after the smoke. The repository already contained historical `.playwright-cli` material outside this task's ownership, so no deletion of that shared directory was performed. The real local harness has one implicit superadmin, not independently authenticated browser principals; deployed read-versus-edit authorization is therefore established by the APISpec lifecycle assertion and Elm permission DOM tests. The browser reported one existing `Unexpected token '<'` console error while loading the runtime configuration, but all exercised Observation REST requests and UI actions succeeded.
